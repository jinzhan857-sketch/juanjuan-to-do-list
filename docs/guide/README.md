# GitHub 怎么看，文件名字是什么意思

第一次来，先看[卷卷首页](../../README.md)。想知道下一步做什么，打开[开发总计划](https://github.com/jinzhan857-sketch/juanjuan-to-do-list/issues/1)。不需要先阅读代码记录。

## 你打开的是什么页面

| 页面 | 大白话解释 | 什么时候看 |
| --- | --- | --- |
| Code，代码与文件 | 仓库文件夹和首页介绍 | 第一次了解项目，从这里开始 |
| Issues，任务 | 要做什么、为什么做、怎么判断完成 | 查看下一步和任务进度 |
| Pull requests，改动审阅 | 一次准备合入项目的修改，包含说明和验证结果 | 核对某项工作实际改了什么 |
| Commit，代码记录 | 保存一次修改时留下的记录，可以看到前后代码差异 | 开发者追查某个版本或具体改动 |
| Actions，自动检查 | GitHub 上运行检查或其他自动流程的地方 | 查看自动检查是否通过 |

文件列表中文件名右侧的一列是最近一次修改的提交说明，不是目录介绍。固定用途见[首页目录表](../../README.md#文件夹分别放什么)，进入各目录也可阅读 README。

如果看到红绿代码，就是打开了改动对比页。它用于追查修改，不会像产品说明一样解释整个项目；可以回到[首页](../../README.md)或原任务。

## b35936b、C01、#2 分别是什么

`b35936b` 是 Git 自动生成的代码记录编号，像一张保存记录的指纹，不是给产品起的名字，也不需要记住。它对应[整理前的应用代码记录，2026 年 9 月 7 日](https://github.com/jinzhan857-sketch/juanjuan-to-do-list/commit/b35936b0c760b57263b068c3a1f204f28bfeb24d)。点击该链接会进入代码对比页，核对为什么某两份文件不同。

`#2` 是 GitHub 自动分配的任务编号，用来稳定链接到一项任务。任务标题可以改得更清楚，编号和链接不变。

`C01`、`V01` 是先前给当前版本任务和 3.0 任务加的内部索引。它们方便对照最初的任务表，不需要出现在标题里。阅读时直接看中文任务名和 GitHub 编号即可。

## 常见说法是什么意思

| 说法 | 具体含义 |
| --- | --- |
| 本地 | 目前这台电脑上的文件或浏览器数据 |
| 未提交改动 | 电脑里的代码已经改了，但这些改动还没存进 Git 的修改记录 |
| 推送 | 把本机保存的修改记录传到 GitHub |
| 分支 | 单独处理一项修改的工作线，完成并检查后再合入主分支 |
| main，主分支 | 仓库默认展示的主要代码与文档 |
| 基线 | 一份已确认内容、版本和检查结果的起点，后续可以据此比较变化 |
| 构建 | 用明确步骤生成准备发布的网页文件 |
| 验收 | 按事先写好的标准实际检查，确认结果正确 |
| 接口或数据合同 | 约定程序之间传什么字段、格式和结果，以及缺少信息时怎么处理 |
| 迁移 | 更换数据结构或保存位置时，把旧数据完整转过去 |

例如现在的[下一项任务](https://github.com/jinzhan857-sketch/juanjuan-to-do-list/issues/2)，意思就是：电脑里的卷卷比 GitHub 更新，需要把应保留的最新代码存进去，并让下载者能运行与这份代码匹配的检查。

## 文件名不用靠猜

`README.md` 是一个目录的说明书。GitHub 通常会在文件列表下显示它。根目录 README 介绍整个项目，子目录 README 解释该目录。开发者常用英文文件名，阅读入口和说明用清楚的中文。

| 名字 | 用途 | 先看什么说明 |
| --- | --- | --- |
| `index.html` | 当前网页源码，含界面和大量业务逻辑 | [当前系统怎么工作](../architecture/README.md) |
| `api/` | 已有的 AI 服务接口代码 | [AI 服务目录说明](../../api/README.md) |
| `dist/` | 当前用于发布的网页文件，可能比本地源码旧 | [发布说明](../development/RELEASE.md) |
| `docs/` | 产品、开发、设计和验证文档 | [文档阅读导航](../README.md) |
| `scripts/` | 开发辅助脚本 | [脚本目录说明](../../scripts/README.md) |
| `diagrams/` | 历史图稿；目前只提交目录说明 | [图稿说明](../../diagrams/README.md) |
| `.github/` | GitHub 的任务与改动说明模板 | [协作模板说明](../../.github/README.md) |
| `.openai/` | 已有 Sites 发布配置 | [发布说明](../development/RELEASE.md) |
| `AGENTS.md` | Agent 接手项目时要遵守的规则 | [接手规则](../../AGENTS.md) |
| `STATUS.md` | 当前状态、已知问题和接手记录 | [当前状态与接手说明](../STATUS.md) |
| `CURRENT_STATE.md` | 第一次整理时留下的详细盘点 | [首次盘点](../CURRENT_STATE.md) |
| `V3_CONSENSUS_DRAFT.md` | 3.0 的完整方案与待定事项 | [3.0 完整方案](../V3_CONSENSUS_DRAFT.md) |

后续新增任务和说明，应先告诉读者“这是什么、解决什么、做完得到什么”，再给代码位置、版本编号和技术依据。链接要写清去向，不只放一串编号让人猜。
