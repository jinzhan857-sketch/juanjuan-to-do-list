# 0002 独立后端优先采用 JavaScript

日期：2026 年 11 月 15 日。状态：依据展本次讨论更正实现方向，具体框架与托管组合仍须验证。

## 决策与替代关系

卷卷独立后端优先采用 JavaScript，在 Node.js 环境中实现。保留现有可用代码，按原任务顺序建设，不为可能用不到的机器学习能力提前更换主要语言。未决定引入 TypeScript 或特定后端框架。

本记录替代 [D0.1 共识稿第 2、6 章](../V3_CONSENSUS_DRAFT.md)中“Python 优先”与“优先验证 FastAPI 和 Vercel 组合”的实现偏好；独立后端、确定性规则、数据保护和稳定性要求继续有效。D0.1 与此前盘点保留为历史依据，不删除旧选择。飞书 D0.1 全文仍是旧版本，本次只更新 GitHub 的决策与任务入口，不声称已同步飞书。

## 原因

当前前端与已有 AI 接口均使用 JavaScript。登录、同步、日程、积分、通知、模型接口、配置工作流和简单统计不要求改用 Python。优先沿用现有语言，可减少两套工具与接口衔接的维护成本。

Python 保留为有明确需求时的数据分析、模型评估或训练工具，可以独立使用，不要求整体后端迁移。是否稳定以行为与运行证据判断，不以语言名称或代码数量判断。

## 后端职责与验收不缩减

- 身份验证、账户与数据权限隔离、密钥保护。
- 数据校验、目标与重复组定位、积分结算、确认后执行、持久保存、撤销与重复请求保护。
- 跨设备同步、冲突处理、旧数据迁移、独立备份和恢复验证。
- 模型与工具调用、额度和并发约束、超时与取消、可追踪的错误与配置版本。
- 独立调度、目标地区可访问性、部署与回滚、正常和异常路径检查。

具体响应时间、并发目标、备份与恢复目标及监测方案在 #11、#12 及对应设计任务中明确，本次不凭空增加数值或宣布已满足。
