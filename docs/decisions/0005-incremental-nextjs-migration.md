# 0005 前端渐进迁移与只读待办试点

日期：2026年11月16日。状态：展已确认方向与首个试点，本轮只规划登记，未安装框架、迁移页面或发布。

2026年11月17日补充：展明确V2.7为稳定里程碑，V2.8至V2.9承接渐进迁移。新框架须用独立试用网址，与稳定正式入口并行一段时间，验证和该次授权后再替换，详见[决策0006](0006-version-milestones-and-isolated-rollout.md)。下方P0至P3及原必要依赖继续有效。

## 决定与理由

先在#122定稿聊天框方案与交互，并由#123归档当前系统及行为基线，再迁入新工程，不先在旧HTML完整重做新UI。首个Next.js试点为只读待办，覆盖真实读取、筛选、计数、详情、路由与构建。先通过范围小、无业务写入的流程核对维护收益，避免一次重写全部功能。

#9继续负责可复用职责边界，#124作为其子任务提供试点必要读取与展示状态模块，不安装框架、不搬完成撤销或积分宠物写流程。#106已通过PR #125隔离启动自测，成果与原始失败由其最终交接证明；不因框架方向改变而返工或扩大#106。

## 必要边界

首个试点前满足#106及#124验收合入、当前系统与行为存档、#122的A阶段定稿和本批具体方案确认。依赖版本、组件状态归属、路由、构建与托管、旧库连续性、回退分别可审查，未经批准不采用具体依赖或宿主。

不要求先完成整个#9、全部UI或账户后端。只读试点不等待#122的B阶段，输入框实现随助手迁入；#123不等待#9整体关闭，#9也不等待迁移全部完成。后续每次迁入一条写流程，先拆该流程必要业务与持久保存边界，复用同一规则与真实模块，不复制业务算法或长期旧新兼容桥。

#63保留全主题控件与外观职责，#61保留首页信息栏职责，#34保留3.0双端布局及验收；由总计划明确承接阶段，不能无限后移或因迁移取消。#104、#119及独立修复继续按自身范围推进，不混入只读试点。#110、#117未解决，换框架与样稿都不能自动销账。
