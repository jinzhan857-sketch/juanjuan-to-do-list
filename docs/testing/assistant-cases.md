# 助手案例库与分批验收

本页用于复用案例和正确规则。它不是模型训练成果，也不把案例数量当作正确率。完整输入与预期在[本轮固定题集](../audit/2026-11-16/issue115/batches-v1.json)。每批40个独立案例，续答属于同一案例，API请求另外累计。

A批使用已见核心题及开发变体。先修复A批问题，并重复关键多轮。B批对应相近能力，改变措辞、标题、日期组织和组合，必须在A批通过后运行。B批修复后回归A批。C批自由度更高，增加讨论转创建、闲聊续接、模糊指代、信息冲突、跨日、引用和长列表；必须在B批通过后运行。C批出现问题立即保留并向展报告，不自行调优C批或创建D批。D批由展决定。

固定题集版本为abc-v1。运行报告记录题集SHA256和应用、接口、共用模块的组合SHA256。先固定预期再运行，不通过后改预期换绿灯。旧失败报告保留，不能用后来的成功覆盖。

## 可复用规则与已知失败类型

| 场景 | 正确规则 | 最小失败及处理 |
| --- | --- | --- |
| 日期已给，未要求时刻 | 直接形成全天候选，不为时刻或评分多问 | 旧程序拒绝全天重复组；原断言保留并标明产品规则已替代 |
| 多项独立事项 | 一项一卡，重复组一组一卡 | 托管单动作合同丢条，使用共用候选合同 |
| 改口 | 稳定卡片身份，版本递增，旧版执行入口拒绝 | AST10旧时段再次新建，按当前版本和持久消息校验 |
| 所有同编号事项 | 根据完整标题匹配全部类型，包括项目、考试等 | 模型只枚举两项而漏第三项；统一修改用scope和uniform，由程序展开匹配集合 |
| 统一开始时间 | 有时长保留，没有时长默认一小时 | 模型追问结束时间或改变时长；共用模块计算候选结束时间，仍须确认 |
| 创建后编辑 | 修改真实原记录，保留原创建内容和修改历史 | 卡片保存recordIds与operationId，更新动作绑定原快照 |
| 未知编号 | 整轮必要追问，不猜相似编号，不先改已匹配部分 | 原始模型答复已保存；不完整或冲突结构不进入写库 |
| 批量确认故障 | 所选全部提交或回滚，完成后发布内存 | 合成故障覆盖业务、操作历史、最终消息中断与并发 |

## 案例如何收拢

每个入库案例保存原输入与续答、预期、模型路径、原答、解析、卡片身份版本、用户确认范围、数据库前后及重开结果、运行版本和费用。成功与失败分开标记，失败修复后仍保留首次证据。只收合成数据和本轮指定的七项，不收密钥、私人备份或日常资料。

通过案例用于回归、少量提示示例候选及项目知识检索。测试留出题不能同时拿去调优后继续称为未见题。将来若要做模型微调、偏好训练或强化学习，需要另建训练、验证与测试隔离集，并单独确认成本和服务能力；目前仅交付软件测试与项目案例库。

实际通过、失败和未测范围以[本轮实施报告](../audit/2026-11-16/issue115/implementation.md)和Issue #115最新交接为准。
