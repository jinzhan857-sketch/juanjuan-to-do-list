# 文档导航

本目录说明当前产品、实际实现、验证依据和后续方向。目录按用途划分，不按聊天先后顺序堆放。

不熟悉 GitHub 的页面、文件名和编号，先看[GitHub 怎么看，文件名字是什么意思](guide/README.md)。

## 推荐阅读顺序

1. [仓库首页](../README.md)：理解卷卷和当前阶段。
2. [当前状态](STATUS.md)：区分仓库、本地改动与已部署版本。
3. [产品与使用说明](product/README.md)：理解日程、待办、积分、宠物和确认流程。
4. [当前架构](architecture/README.md)、[数据说明](architecture/DATA.md)、[AI 接口说明](architecture/AI.md)：找到实现与边界。
5. [开发说明](development/README.md)、[测试说明](development/TESTING.md)、[发布与恢复](development/RELEASE.md)：准备运行与修改。
6. [路线图](ROADMAP.md)：选择满足前置条件的下一项任务。
7. [3.0 全文](V3_CONSENSUS_DRAFT.md)、[设计决策](decisions/README.md)：理解演进约束与未定事项。

Agent 还必须阅读根目录 [AGENTS.md](../AGENTS.md)。

新聊天先核对[接手说明](HANDOFF.md)，确认本轮范围与未完成事项，再选择开发任务。

## 目录用途

| 路径 | 内容 | 更新规则 |
| --- | --- | --- |
| `product/` | 当前产品说明、使用路径与规则 | 行为变更时同步更新 |
| `architecture/` | 当前模块、数据与 AI 边界 | 随实现更新，不用未来设计替代现状 |
| `development/` | 启动、测试、发布与恢复 | 命令实际验证后再写为可用 |
| `decisions/` | 设计选择、原因、状态与后续决策入口 | 保留决策变化的原因 |
| `reference/` | 飞书来源、参考项目和素材取舍 | 来源不直接代表已实现能力 |
| `history/` | 原始历史测试记录 | 保留旧失败，不充当最新通过证据 |
| `audit/` | 带日期的盘点和检查证据 | 保留快照，不覆盖成新一轮报告 |
| `STATUS.md` | 当前状态入口 | 发生重要交付后更新 |
| `CURRENT_STATE.md` | 2026 年 11 月 14 日首次盘点 | 历史基线，阅读时先看快照口径 |
| `V3_CONSENSUS_DRAFT.md` | 3.0 完整共识与范围 | 调整正文需产生新版本并同步飞书全文 |
| `ROADMAP.md` | 总路线图与任务入口 | 只负责导航，状态以 Issue 为准 |

## 信息放在哪里

产品和工程事实写在对应文档，待做事项及状态写在 Issue，具体改动和验证写在 PR，实际发布对应版本与发布记录。文档之间用链接关联，不复制多份待办清单。

飞书与 GitHub 的 3.0 方案都保留全文，当前 D0.1 正文保持一致。新增的开发文档与任务导航在 GitHub 维护；不要把聊天或只有权限才能打开的外部来源当作唯一实施说明。

本地 `diagrams/`、原始测试文件和个人备份的归档口径见[来源与素材](reference/README.md)。
