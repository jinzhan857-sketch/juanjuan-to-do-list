本文说明当前代的产品概念和使用路径。实现与验证范围见[当前状态](../STATUS.md)，未来要求见[3.0 共识稿](../V3_CONSENSUS_DRAFT.md)。

## 卷卷解决什么问题

把零散表达整理为可管理的事务，通过日历、待办、规划建议与宠物反馈，帮助用户持续行动。事务分为有执行日期的日程，以及没有固定执行时间的待办。

| 入口 | 使用方式 |
| --- | --- |
| 首页 | 查看选定日期的日程、积分和宠物状态，反馈任务完成情况 |
| 计划 | 按日、周、月查看安排，进入统计与规划相关入口 |
| 待办 | 查看近期和长期事项，创建、编辑、完成或删除 |
| 助手 | 选择事务、规划或聊天模式，发送自然语言请求 |
| 我的 | 设置外观、模型、个人记忆、备份与其他偏好 |

## 典型使用路径

### 创建事务

从发布入口选择日程或待办，填写原始内容，使用当前识别入口整理，再核对标题、备注、分类、日期和时间后保存。具体时间和全天等类型要与用户实际意思一致。

发布内容以原文首个非空行作为定义，后续行作为备注；明确同行附加信息可移入备注，其余保留原句、日期时间、否定和标点。首尾空白规范化，备注内部空行及重复行保留，超长提示后由用户调整；手改字段优先，评分继续独立。#60实现和组合待验边界见[交付报告](../audit/2026-11-15/issue60-publisher-content.md)。待办不应因为识别推测而被强制添加日期或优先级。历史测试中的旧预期可能与此不同，不能直接恢复旧规则。

发布表单左侧为“AI 识别”，右侧初始为“快速发布”，识别成功后为“确认发布”，编辑旧事务为“保存修改”。可直接发布，基础分只读。快速发布沿用本地分类规则自动填写分类，例如“递交作业”为学业事务；分类可手改，手动选择优先，分类不参与基础分计算。AI 成功后修改表单保留 AI 分数，新建识别失败自动转规则评分并发布；编辑失败保留修改。评分定义和正反例见[快速评分说明](quick-scoring.md)。日期默认今天、全天，手动字段优先，日历始终显示整月。实现和独立验收状态见[#47、#43、#44 报告](../audit/2026-11-15/issue47-publisher.md)。

### 用助手处理事务

事务模式负责查询和提出新建、修改、删除等操作；规划模式依据日程、待办和授权记忆提出建议；聊天模式负责一般交流。建议转为真实数据变更时，进入受控事务流程。

核对确认卡中的目标、日期和影响条数后再执行。单条与整组不是同一种范围，存在歧义应追问；当前已有范围识别缺陷，测试时需使用合成资料。

3.0 中三种模式的自然语言聊天都依赖 AI API。现有源码还有本地降级路径，这属于当前实现，并非 3.0 应继续扩展的聊天方案。

### 查看反馈与备份

日程可以反馈完成目标、正在完成中、完成失败、暂时搁置或没有去做。积分与宠物状态由程序计算，AI 的基础价值判断不等于最终所得积分。

在“我的”数据入口导出 JSON。导入目前会覆盖数据，不能当作跨设备合并；先保留备份，再在隔离测试环境验证。不要对正式资料试验清空、批量修改和导入。

## 当前计分规则摘要

下面是源码现状，不代表已冻结的 3.0 评分设计。位置为 `index.html` 的 `CONFIG`、`ScoreEngine`、`todoScore` 和 `PetSystem`。

| 规则 | 当前实现 |
| --- | --- |
| 日程结算 | 基础分 ×（规划系数＋时间精度加成＋特殊类型加成）×完成状态系数×适用惩罚，结果不小于 0，保留一位小数 |
| 提前规划 | 提前 3 天及以上 90%，2 天 85%，1 天 80%；当天按创建时间分 70%、50%、30% |
| 时间精度 | 大部分时段加 10 个百分点，精确时间再加 5 个百分点，具体按时段配置判断 |
| 完成状态 | 完成目标 70%，进行中 50%，失败 40%，搁置 30%，未做 0% |
| 补录 | 今日 10%，昨日 5%，更早 0%；金钱复盘存在额外加成 |
| 超时与改时 | 按确认延迟、修改时机及原截止时间施加系数，详见源码 `OVERDUE`、`TIMECHANGE` |
| 待办 | 当前 `todoScore` 使用基础分的 70%，日程与待办不是同一套结算公式 |
| 宠物 | 积分关联食物和成长，另有饱度、好感度与跨日结算，不在整理中删减 |

显示预估、正式结算和食物换算还有各自处理，不能只凭此摘要重写整套公式。精确边界与重复结算保护应通过后续规则测试核对。

## 能力边界

本次审阅新增确认的补录、年份、明确本周过去日期、仅月份提示切换待办，以及模糊钟点固定提示，均属待实施行为，唯一规则见[确认规则](../reference/2026-11-15-confirmed-feedback-rules.md)。步骤和验收见[实施接手](../development/HANDOFF_CONFIRMED_RULES.md)，不从本段推定正式网站已更新。

待实施的本轮确认：日期、时间独立识别，单端补一小时及跨日，原文保留与换行备注，详情和首页信息栏，以及全部主题默认关闭阴影与灰白配色，见[确认规则](../reference/2026-11-15-confirmed-feedback-rules.md)。本段不表示这些要求已上线，原有实现描述按当前代码核对；任务入口为#57至#66。

当前没有可用的账户与业务云端同步；数据主要在当前浏览器。现有附件能力保留，不代表 3.0 已确定新增云端图片存储。桌面、安卓和 iPhone 的完整体验，以及普通网页推送，都需要后续实机验证。

产品规则变化要同步本文与相关测试；实现位置见[当前架构](../architecture/README.md)，待办事项见[路线图](../ROADMAP.md)。
