# AI 接入与动作说明

这是当前代码的说明，不是已经稳定发布的独立 API 合同。正式合同抽取与跨端统一属于后续任务。

## 两条模型路径

| 路径 | 入口 | 条件与边界 |
| --- | --- | --- |
| 托管 | 前端请求同源 `/api/ai`，文件为 `api/ai.js` | 需要宿主路由、模型 Key 和 Redis REST 等配置；静态服务器不会自动执行 |
| 自定义 | `AIService` 读取用户填写的接口、模型和 Key | 浏览器直连，服务需允许浏览器请求；Key 当前保存在本设备 localStorage |

服务端导出 CommonJS `handler(req, res)`，依赖类似 `res.status().json()` 的宿主方法，没有独立监听端口的启动程序。

服务端只记录这些环境变量名称，不记录值：`DEEPSEEK_API_KEY`、`KV_REST_API_URL`、`KV_REST_API_TOKEN`、`RATE_LIMIT_SALT`、`OWNER_STATS_TOKEN`。在实际接入宿主前不要创建可公开下载的 `.env` 或把密钥放前端。

## 当前请求与结果

| 用途 | 当前输入 | 当前行为 |
| --- | --- | --- |
| 评分识别 | `POST`，`title`、`device_id`，可带 `client_date` | 返回标题备注、分类、基础分、建议和日期时间等整理结果 |
| 助手 | `POST`，`mode: agent`、`message`、`agent_role`、`context`、`device_id` | 根据事务、规划或聊天指令返回结构结果 |
| 运营统计 | `GET` 且 `stats=1` | 需管理口令，非业务数据查询接口 |

当前设备标识要求 24 至 64 位字母数字。输入长度、日期、时间与动作都有程序清洗，但清洗不等于全部语义正确。

结果类型主要为 `chat`、`clarify`、`query`、`proposal`、`batch_proposal`、`recommendation`。动作包含日程和待办的新建、修改、删除，日程批量创建、整组修改与删除，以及日程转待办。具体支持情况要同时核对前端、服务端与实际版本。

已有对象通过真实 `target_id` 定位；重复组优先使用 `series_id`，并核对日期范围、星期、课程与时间。模型字段使用 `exec_date`、`time_type` 等形式，浏览器对象常用 `execDate`、`timeType`，当前映射散落在 UI 方法中。

新建和修改前核对必填信息、目标范围与用户确认。最终执行结果以数据库状态和操作记录为准，不能以模型回复“已完成”为准。

## 已知差异

本地服务端 `compactAgentContext` 丢弃日程组身份；本地降级对指定单天的输入可能返回整组动作。提示词写了正确规则，仍不代表程序和所有链路已做到。复现证据见[现状清单](../CURRENT_STATE.md)。

前端 `CUSTOM_*_PROMPT` 与服务端指令分别维护，结构清洗也有重复。后续需统一数据与动作说明，并将角色指令、上下文选择、工具和界面文案分开。

当前 `api/ai.js` 的设备额度为每日 20 次，IP 额度为 50 次，不能误写成 3.0 的全站额度。3.0 已提出访客设备 10 次、账户 20 次、全站公共调用 50 次，并要求可配置；组合规则、重试计数和重置口径还需设计。

当前源码中有模型标识，不据此保证供应商仍支持该型号。正式调用前验证实际可用模型和费用，本轮不发起模型请求。

3.0 中聊天依赖模型，快速发布按规则工作；确定性日期、积分、校验和执行交给程序。工作流不能关闭权限与写入保护。完整要求见[共识稿](../V3_CONSENSUS_DRAFT.md)。
