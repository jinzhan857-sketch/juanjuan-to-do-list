# AI 接入与动作说明

这是当前代码的说明，不是已经稳定发布的独立 API 合同。正式合同抽取与跨端统一属于后续任务。

产品主线是准确记录与处理生活事务，规划、聊天和主动帮助按授权读取相关事实；定位见[产品说明](../product/README.md)。Anthropic运行架构与nanoMuse局部参考的取舍见[借鉴方案](../reference/agent-learning-plan.md)，选中原则已细化到原任务，不据该方案宣称现有接口已支持完整后台执行。

## 两条模型路径

天气在聊天模式中由本地工具查询，不调用模型。地点依次取本次明确输入、当前天气对话、已授权且唯一的居住地点记忆；不再将本次输入和记忆拼接后按城市关键词抢先命中。已有香港坐标表仅用于名称解析后的查询，不参与来源优先级。

天气结果与追问在消息 meta.weather 中保存本次地点、相对日期与是否等待地点补充，UI.agentContext 只从当前聊天最近 12 条消息传递。追问时可直接回复城市；查询成功后，使用“那上海呢”“换成上海”或“我在上海”等明确表达续答，避免将普通聊天当作城市。城市续答沿用所问日期，日期续答沿用城市；最新助手消息不是天气时结束续答上下文。不扩展记忆授权或资料范围，不迁移历史消息。

无地点时追问，地理编码无结果时要求具体地点；HTTP 失败、非法坐标、缺少数值或 JSON 损坏显示服务不可用，超时单独说明。天气请求使用现有取消入口，取消后不保存迟到结果，旧请求结束不清除新请求控制器。验证与真实服务连通性分别记录在[#7 报告](../audit/2026-11-15/issue7-weather.md)。

| 路径 | 入口 | 条件与边界 |
| --- | --- | --- |
| 托管 | 前端请求同源 `/api/ai`，文件为 `api/ai.js` | 需要宿主路由、模型 Key 和 Redis REST 等配置；静态服务器不会自动执行 |
| 自定义 | `AIService` 读取用户填写的接口、模型和 Key | 浏览器直连，服务需允许浏览器请求；Key 当前保存在本设备 localStorage |

服务端导出 CommonJS `handler(req, res)`，依赖类似 `res.status().json()` 的宿主方法，没有独立监听端口的启动程序。

服务端只记录这些环境变量名称，不记录值：`DEEPSEEK_API_KEY`、`KV_REST_API_URL`、`KV_REST_API_TOKEN`、`RATE_LIMIT_SALT`、`OWNER_STATS_TOKEN`。在实际接入宿主前不要创建可公开下载的 `.env` 或把密钥放前端。

## 当前请求与结果

| 用途 | 当前输入 | 当前行为 |
| --- | --- | --- |
| 评分识别 | `POST`，`title`、`device_id`，可带 `client_date` | 返回标题备注、分类、基础分、建议和日期时间等整理结果 |
| 助手 | `POST`，`mode: agent`、`message`、`agent_role`、`context`、`device_id` | 根据事务、规划或聊天指令返回结构结果 |
| 运营统计 | `GET` 且 `stats=1` | 需管理口令，非业务数据查询接口 |

当前设备标识要求 24 至 64 位字母数字。输入长度、日期、时间与动作都有程序清洗，但清洗不等于全部语义正确。

结果类型主要为 `chat`、`clarify`、`query`、`proposal`、`batch_proposal`、`recommendation`。动作包含日程和待办的新建、修改、删除，日程批量创建、整组修改与删除，以及日程转待办。具体支持情况要同时核对前端、服务端与实际版本。

已有对象通过真实 `target_id` 定位；重复组优先使用 `series_id`，并核对日期范围、星期、课程与时间。模型字段使用 `exec_date`、`time_type` 等形式，浏览器对象常用 `execDate`、`timeType`，当前映射散落在 UI 方法中。

新建和修改前核对必填信息、目标范围与用户确认。最终执行结果以数据库状态和操作记录为准，不能以模型回复“已完成”为准。

## 重复组身份合同

日程本地字段为 seriesId，模型上下文和整组动作 rule 使用 series_id。合法值是长度 1 至 80 的字符串，按 JavaScript UTF16 长度计算，不得有首尾空白、ASCII 控制字符或 DEL。编号按原值精确比较，不强制转换类型、不截短、不去空白。字段缺省或 null 表示未提供身份，空字符串属于非法值。

前端与服务端上下文白名单只传合法编号，非法或缺失值发送 null，不改写原始数据。整组模型结果携带非法编号时转为 clarify，托管接口还核对编号是否出现在本次压缩资料中。自定义结果和规划建议采用时仍由前端校验原请求、已有数据与编号。已有编号的目标必须原样带回编号，否则拒绝生成或执行确认卡，不降为标题匹配。

不带编号的原有日程继续使用已有的名称、日期、星期与原时间范围匹配，不新增迁移或兼容路径。多组歧义仍追问；模型猜出一个真实编号也不能绕过原请求校验。确认卡条数、执行与撤销均按同一组目标处理，确认后资料或组成员变化则停止写入。证据见[#5 报告](../audit/2026-11-15/issue5-series.md)。

## 公共额度日期与模型日期

#29将可信额度日与用户日期分开。按展于2026年11月15日弹窗确认，公共额度以服务端北京时间每天00:00换日，设备每日20次，IP每日50次；展随后明确增加公共接口全站每日100次。请求进入handler时只取一次计数日；设备键、IP摘要与键、全站键、活跃、调用、成功、失败及超限均归该日，即使Redis等待或模型返回跨午夜也不换日。

有效client_date仅用于模型理解“今天”和日期上下文，不参与任何额度或运营统计键。缺省或非法用户日期回退到本次可信计数日。统计查询不传日期或传非法日期时用请求开始时的北京时间日期；有效历史日期仍可查询。

新日重置通过日期键切换完成，不依赖旧键到期。额度与指标键仍在首次增加后设置86400秒过期，后续增加不续期；活跃键仍每次请求设置2678400秒过期。保留旧键策略，不迁移、不双读、不增加兼容路径。

服务端仍先增加设备和IP计数并判断这两项限额，通过后再增加全站计数并判断100次上限，最后调用模型；失败、超限不退款，客户端取消也不保证服务端停止。设备或IP已超限的请求不增加全站计数；全站拒绝不调用模型。429的limit_scope分别为device、ip、global，与前端三种短提示对应。退款目标由#38继续处理，不因#29关闭而完成。业务完成数量及积分统计属于另一套数据，不与这里混用。专项与边界见[#29报告](../audit/2026-11-15/issue29-quota-date.md)。

## 已知差异

#5 已补齐前端上下文、托管压缩与模型返回中的组身份合同，详见下方。#4 已修复本地降级把指定单天误判为整组的问题：先按原话判断单条或整组，再按日期、名称与组身份要求唯一目标。范围不清、同名多组或目标不存在时追问，不取第一条猜测。

本地或模型的修改与删除建议在生成确认卡前都核对原请求，禁止把单天请求扩为批量。规划建议转确认卡也采用同一校验。确认卡记录目标数据快照，执行入口重新校验；目标新增、删除、日期或内容变化后停止写入，要求重新生成确认卡。没有快照的历史待确认卡也须重新生成，不迁移旧卡。详情编辑成功后重新记录范围并返回确认卡供核对。

两项 P1 复审修复后，原话的目标范围出现多个不同日期时先追问，不让第一个日期覆盖后续排除或更正；同一天的不同写法仍按一个日期处理。备注或修改值里的日期不当作目标日期。原有单条、整组、身份和确认快照保护保留，证据见[P1 修复报告](../audit/2026-11-15/review-p1-fixes.md)。

这些检查使用本地合成数据验证，不代表真实模型链路已经验收。历史复现见[现状清单](../CURRENT_STATE.md)，修复证据见[#4 报告](../audit/2026-11-15/issue4-scope.md)。

前端 `CUSTOM_*_PROMPT` 与服务端指令分别维护，结构清洗也有重复。后续需统一数据与动作说明，并将角色指令、上下文选择、工具和界面文案分开。

当前 `api/ai.js` 按展于2026年11月15日的新确认，设备额度每日20次，IP额度50次，全站公共接口额度100次；自己的API直连不进入这些计数，当前无本人身份豁免。3.0 已提出访客设备 10 次、账户 20 次、全站公共调用 50 次，并要求可配置；组合规则、重试计数和重置口径还需设计。

当前源码中有模型标识，不据此保证供应商仍支持该型号。正式调用前验证实际可用模型和费用，本轮不发起模型请求。

3.0 中聊天依赖模型，快速发布按规则工作；确定性日期、积分、校验和执行交给程序。工作流不能关闭权限与写入保护。完整要求见[共识稿](../V3_CONSENSUS_DRAFT.md)。
