# 数据存储与保护

本文记录当前格式及已知风险，未来账户、同步与迁移设计见[3.0 方案第 9、10 章](../V3_CONSENSUS_DRAFT.md)。

## 当前保存位置

当前业务数据主要保存在浏览器 IndexedDB，数据库名 `juanjuan-pet`，结构版本 3。运行中的内存镜像是 `S`。

| 对象仓库 | 内容与关键关系 |
| --- | --- |
| `tasks` | 日程；常见字段有 `id`、`title`、`execDate`、`timeType`、`baseScore`、`status`；部分本地新增日程含 `seriesId`、`seriesRule` |
| `todos` | 待办；`id`、标题备注、分类、`baseScore`、`done`、完成时间与所得分 |
| `chats` | 会话元信息 |
| `messages` | 消息、确认卡和结果，通过 `chatId` 关联会话 |
| `memories` | 用户记忆与授权使用的资料 |
| `operations` | 已执行动作、变更前后快照和撤销状态 |
| `kv` | 宠物、逐日统计、自定义标签、资料框等；资料框为本地新增能力之一 |

主题、草稿、当前会话、设备标识和模型配置等另存 localStorage。当前自定义 API Key 也在 localStorage，不能把此做法当作 3.0 密钥管理已定方案。

存储按站点来源区分。不同域名、端口、设备或浏览器不自动共享；清理站点数据、使用临时浏览器或更换来源会影响可见数据。仓库中的 JSON 文件不是浏览器实时数据库。

## 发布跨日字段

#59按展确认增加可选endDayOffset，值只能为1，且仅用于精确时间，表示次日结束。execDate仍为实际开始日。缺省为既有同日含义，不迁移、不补写旧记录，不重算旧积分。截止、显示和导入撤销共用该语义，非法字段整份拒绝，见[交付报告](../audit/2026-11-15/issue59-publisher-time.md)。

## 模型请求中的资料

本地保存不等于使用 AI 时没有资料离开设备。聊天会提交输入及按角色选择的上下文，可能包含近期事务、授权记忆和对话。托管接口还会压缩上下文；自定义接口由浏览器直接请求用户设置的服务。

记忆授权只决定相关应用逻辑是否选用资料，不能据此宣称没有任何网络传输。排查时先用合成内容，不把用户原文、Key 或完整请求写进公开记录。

## 备份与导入

当前 `UI.exportData` 导出应用名、版本 `2.2`、导出时间，以及日程、待办、会话、消息、记忆、操作、宠物、逐日统计、自定义标签与外观。本地新增版本还包含 `memoryGroups`。API Key 和完整 localStorage 不在这份业务备份中。

#6 已将导入改为一次跨仓库事务，保存成功以事务 complete 为准。导入先校验当前 2.2 备份的集合、编号、日期时间、附件、聊天与操作引用、宠物及统计字段。缺少或重复编号、非法字段会拒绝整份文件，预览与导入不再过滤、截断或自动去重；不增加旧格式兼容。导入仍为覆盖恢复，不是合并同步。

#64 为校验错误补充集合、记录序号、简短身份与字段路径，导入窗口持续显示首个错误；解析异常不回显文件片段。严格拒绝与事务保护不变，详见[验收报告](../audit/2026-11-15/issue64-import-errors.md)。

P1 复审补齐现有业务字段校验：日程状态仅接受 CONFIG.STATUS 中的值，未结算状态沿用缺省或 null；所得分存在时必须为有限的非负数字，状态修改次数存在时必须为非负整数，已结算日程不得缺少这两项；结算时间存在且非 null 时必须为有限的非负时间戳。导入和撤销快照共用校验，损坏字段直接拒绝，不修补或迁移。验证见[P1 修复报告](../audit/2026-11-15/review-p1-fixes.md)。

预览后读取同一份数据库快照，确认时在写事务内再次比对；期间资料变化则停止覆盖。所有日程、待办、聊天、消息、记忆、操作与已导出的 kv 项一起提交。失败由 IndexedDB 回滚，内存仅在事务完成后更新。外观设置仍属 localStorage，业务提交后单独恢复，失败会明确提示外观未完全恢复，业务数据不会被误报为回滚。

升级、发布回退与数据恢复是三件不同的事。回到旧页面不会自动还原数据库，也可能遇到旧页面无法识别新字段的情况。未做恢复演练前，不对真实数据执行试验导入或迁移。

## 当前批量写入保护

DB.request 处理单仓库请求并等待事务完成，DB.batch 在一个事务内校验前置快照并提交整批改动，commitDataChanges 在提交成功后发布内存更新。事务内部不等待网络或异步业务逻辑。组操作、助手单条动作和日程转待办将业务记录、操作记录与最终确认消息一起提交；撤销也一起提交。导入和撤销共用业务记录与快照校验，缺少快照、重复编号、修改前后目标集合不一致或非法记录字段均拒绝，不写回损坏的历史快照。重复确认受界面运行锁和数据库快照保护。其他页面或标签修改过资料时拒绝覆盖并提示重新加载。

本轮还将聊天及引用删除、全部聊天清理、附件清理、标签批量改名、记忆卡全部保存、资料框改名或删除转移、表单转待办、旧任务与新任务替换及清空重置接入整体提交。没有改动积分算法，单条状态结算与宠物奖励的规则一致性仍按 #8、#28 分别验收，不把本轮当作全部计分路径已完成原子化。已有兼容函数不扩展。

故障证据、复现和边界见[#6 报告](../audit/2026-11-15/issue6-atomicity.md)；独立专项矩阵及可选人工步骤见[#37 检查矩阵](../audit/2026-11-15/issue37-storage-matrix.md)。原生浏览器验证仅使用 4174 测试来源与合成数据库，不操作正式资料。事务完成和整体回滚的语义依据 [W3C IndexedDB 规范](https://www.w3.org/TR/IndexedDB/)。

## 3.0 已确定的保护要求

访客本地可用，登录后通过 Supabase 保存和同步，首版接受手动同步。登录失效时保留本地使用和待同步修改，跨账户必须隔离。升级后保留原有数据，采用有版本的迁移、独立备份与恢复验证。

合并、删除传播、冲突和重试等细节尚未冻结，进入设计任务。迁移真实资料前先明确数据清单、合成旧数据样本、失败恢复和验收结果，不新增未经同意的兼容处理。

个人 JSON 备份不提交，即便仓库私有也一样。工程样例只使用合成数据。待做事项进入[路线图](../ROADMAP.md)。

## #8 完成数量与状态结算

产品口径以[产品说明](../product/README.md#完成数量与统计口径)为准。completionSummary从S.tasks当前done状态的execDate与S.todos当前done状态的completedAt读取完成数量，日期按浏览器本地日期处理；本轮固定Asia/Shanghai。首页与报告共用该读取入口，读取不修改存储。不按确认时间猜测日程执行归属，也不迁移缺失完成时间的旧待办。

dayStats.points保留实际结算日的带正负号差额流水。dayStats.done保留原有确认日状态变化净量，不再用于展示执行日期完成数或周趋势；因此旧流水done与当前已完成记录数量不要求相同。旧completed误读已消除。没有批量重写旧dayStats，已删除记录不会作为当前完成记录计入统计。

日程状态与待办完成将记录、dayStats及宠物一次提交，事务完成后更新内存。重复同一状态不写库、不重算、不消耗修改次数；两个待办确认或并发状态操作最多提交一次。持久资料变化则拒绝覆盖；提交失败保留原记录、流水、宠物，提交后渲染失败明确提示已保存。正差额仍按既有食物和成长规则奖励，负差额只修正积分流水，不追扣已经喂给宠物的食物；没有扩展#28编辑计分范围。

宠物显示改为只读当日进食，不在渲染时偷偷变动内存；当日进食日期重置与本次结算共同保存。报告与可复用合成基线见[#8报告](../audit/2026-11-15/issue8-completion-statistics.md)，#28可复用scripts/completion-stats-fixture.cjs与专项入口，但编辑计分一致性仍待该任务独立实施。
