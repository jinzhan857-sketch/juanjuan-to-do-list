# 开发总计划入口

[版本定位与开源借鉴](product/VERSION_POSITIONING.md)解释1.0到4.0及过渡阶段；[具体借鉴方案](reference/agent-learning-plan.md)先供审核，Anthropic作为运行机制主要参考，nanoMuse保留局部参考。审核后才把选中的新增实施细节并入原任务；当前顺序、必要依赖和原位置勾选保持，不拆完成与未完成，3.5、4.0仅为候选。

[打开总计划 Issue #1](https://github.com/jinzhan857-sketch/juanjuan-to-do-list/issues/1)：唯一执行队列、已完成成果、3.0和可选研究都在这里。查看进度直接进入总计划，本文只解释使用方法，不复制进度；页面原生子任务计数不代表后来登记的全部任务。

## 从哪里开始

先阅读[当前状态与接手说明](STATUS.md)和[已确认规则实施接手](development/HANDOFF_CONFIRMED_RULES.md)，再从总计划选择展授权的具体任务。#2、#3等已完成基础工作不再写成下一项；已关闭任务保留成果，新观察先核对是否已被较新提交修复。[3.0规则设计#11](https://github.com/jinzhan857-sketch/juanjuan-to-do-list/issues/11)可按授权提前讨论，账户同步方向不变。施工顺序不新增逐项关闭的硬前置，仍须核对原有必要依赖。

## 标签是什么意思

| 标签 | 用途 |
| --- | --- |
| 当前版本 | 整理当前版本的代码、检查与发布流程 |
| 3.0版本 | 建设已确认的 3.0 能力 |
| 方案设计 | 先明确规则、边界或验证方案 |
| 总计划 | 汇总阶段任务、依赖与完成情况 |
| 可以开始 | 前置条件已满足，仍需按任务范围执行 |
| 问题修复 | 修复已经发现的错误行为 |
| 功能与工程改进 | 增加能力或改善代码与开发流程 |
| 文档说明 | 完善项目介绍、规则与操作说明 |
| 重复任务 | 已有同一任务，保留记录并链接原任务 |
| 适合新手 | 范围明确，适合第一次参与 |
| 需要协助 | 需要其他参与者协助处理 |
| 需要重新核实 | 问题描述或依据不足，需要核实 |
| 待确认问题 | 需要补充信息或明确决定 |
| 不予实施 | 已决定不实施，保留原因与记录 |

## 如何维护

完成并验收后关闭子任务、核对总计划的勾选并补交付链接，保留已完成条目。取消或被替代的任务保留原因及替代链接。改变依赖时同时核对总计划与对应任务，不删除过去的失败证据。

任务里写具体范围和验收；[任务模板](../.github/ISSUE_TEMPLATE/task.md)用于新建任务，[PR 模板](../.github/pull_request_template.md)记录改动和验证。工作分支使用 `codex/` 前缀。
