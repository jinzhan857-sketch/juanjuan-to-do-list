## 如何维护

总计划正文只保留两张主流程图、原任务顺序、完成勾选、必要依赖提示与资料入口。实施 Codex 按任务范围和授权验收、更新自己的子任务，向总协调 Codex 提交交接；总协调 Codex 核对后同步原位置勾选和两图状态。已完成项保留任务名称与链接，不另加交付段落，不拆成另一份完成清单。

详细交付、复查、受检提交、测试数量、失败证据与未测范围写在对应任务和验证报告，总计划通过任务链接进入，不累加聊天收尾或阶段日志。已有完整记录时不重复搬写，只补缺少的成果入口。取消或被替代的任务保留原因及替代链接。

经展确认改变依赖后，总协调 Codex 与实施 Codex 分别同步总计划与对应任务，推荐施工顺序不自动变成逐项关闭的硬前置。大幅整理正文前先逐字归档，记录来源、时间与校验值，核对任务顺序、状态、流程图和链接后再替换正文；旧评论和快照不删。历史统一从[归档索引](history/README.md)进入，不把旧状态当作当前结论。

任务里写具体范围和验收；[任务模板](../.github/ISSUE_TEMPLATE/task.md)用于新建任务，[PR 模板](../.github/pull_request_template.md)记录改动和验证。工作分支使用 `codex/` 前缀。

## 总协调与实施交接

展于2026年11月16日确认以下分工。本文是总计划修改权限、交接与架构复查协作约定的主要来源，其他入口引用本文；具体结构整理仍由[结构接手](development/STRUCTURE_HANDOFF.md)、#9及#106承接，3.0范围与验收规则由#11承接，不新增重复任务。

### 三方职责与修改权限

| 角色 | 负责什么 | 可以直接做什么 |
| --- | --- | --- |
| 展 | 决定方向、重要产品规则、重大范围与架构变化、费用及发布 | 确认具体方案与授权范围 |
| 总协调 Codex | 统一维护总计划#1正文，核对任务关系、成果与架构一致性 | 在已确认职责内核实并同步完成勾选、成果链接、图中状态及已有决定，不为每次事实同步反复询问展 |
| 实施 Codex | 维护自己获授权的任务、PR、源码与必要文档，执行相关验收 | 继续已获授权工作、记录证据和遗留事项，向总协调 Codex 提交更新，不自行重排或改写总计划正文 |

事实同步、排期和规则变化分别处理。按已确认顺序识别前置已满足的候选任务，不等于获得开工授权；改变任务顺序、必要依赖、需求或验收范围，先列明差异与依据，由展决定。总协调 Codex 不能替展批准新需求、新依赖、兼容、迁移或发布，也不能自行改变实施 Codex 已获准的范围。费用和真实模型调用仍按当轮明确预算，不因共享Key或新工作区取得授权。

额外复查不新增总协调 Codex 的合入审批权。实施、合入、发布分别按展的具体授权执行；任务完成勾选必须有对应成果与验收，模拟、真实模型、隔离Redis、生产服务、原生浏览器、真实手机、合入和发布不能相互替代。

### 怎样交接和知道处理结果

1. 实施 Codex 在原任务或PR下留一条【项目更新交接】评论，使用下方格式。已有报告通过链接引用，不复制长篇经过；未验证事项写明归属和继续条件。交接不能只留在聊天里。
2. 实施 Codex 将评论链接交给展，请展把链接贴到总协调 Codex 所在聊天。这里不设置自动通知或#1待同步索引，不承诺自动监听、消息必达或技术上的权限隔离。
3. 总协调 Codex 读取交接、相关授权和对应版本证据，在同一任务或PR评论区回复处理结果并引用原交接链接：已同步、证据不足待补充、存在冲突待决定，或者无需改总计划。已同步时附实际修改位置或成果链接；建议本身不当作展的授权。
4. 总协调 Codex 暂时不在时，实施 Codex 继续已获准工作，在原评论中标明待总协调同步，并保留交给展的链接。未收到处理结果不算已同步，不因等待交接擅自扩大范围。
5. 多条交接逐条核对。每次写总计划前重新读取最新完整正文，只改有证据的必要部分；发现读取后正文变化，重新读取并合并差异，不拿旧正文整页覆盖。写入后回读核对任务位置、编号、状态、两图和链接；意外覆盖或丢失成果时停止后续写入并留证。
6. 后续换总协调聊天时，由展明确角色并转交未处理链接；接手者读取本文、最新#1和相关任务、PR交接与处理回复，核对待处理事项，不依赖旧聊天一直在线或记住全部历史。链接不全时针对性查找近期任务和PR评论中的交接记录，未找到不能声称没有待同步事项。

```text
【项目更新交接】
任务及实施聊天：
展授权的范围或决定来源：
完成了什么：
Issue、PR、受检提交及合入提交：
执行了哪些检查，结果是什么：
尚未验证或尚未解决的事项及归属：
影响的模块、规则和其他任务：
建议总计划修改的具体位置与内容：
是否涉及顺序、依赖、范围或架构变化：
是否发布、迁移或调用真实模型：
处理状态：待总协调同步
```

### 何时额外做架构复查

按钮颜色、文案等局部小改由实施 Codex 按实际影响验收，不要求所有改动排队。涉及跨模块共同规则、数据写入与确认撤销、积分宠物、AI字段合同或模块依赖方向变化时，实施 Codex 在原任务或PR交接中说明调用关系、影响范围、最小方案与验证方法，交总协调 Codex 复查。重大结构或产品规则变化仍先由展确认；已获授权的实现不因新增复查约定自动收回，复查中的独立准备工作可以继续。

复查核对实际代码与行为证据，关注职责边界、重复规则、程序校验、提交与失败入口，以及说明能否找到真实实现。发现问题时区分当前缺陷、维护风险和未来优化，给出具体位置、影响与最小处理方案，不把所有问题升级成紧急重构；涉及关键写入保护或关键检查退步，按原停止条件处理。复查结论、未测范围和遗留归属写回原任务或PR，不以整理文档代替实现或验收。

### 旧要求怎样切换

展转交下面的提示词及本文链接给现有实施聊天，实施 Codex 阅读后在原任务或PR交接中注明采用本约定。新聊天从根目录AGENTS.md进入本文。本文不会自动送达已开启聊天，本轮记录约定不包含发送消息或修改GitHub权限配置。

完成切换后，旧提示词或接手要求中的“各实施聊天自行同步总计划”，改为“实施 Codex 提交交接，总协调 Codex 核对后同步”。实施 Codex 更新自己的任务和PR的职责保留。已有明确授权先保留，按原范围收尾并记录交接后再切换；与新分工冲突且切换不明确时，交展决定，不默默撤销或扩大旧授权。历史原文与成果继续保留。

确需委托另一实施 Codex 修改总计划时，使用一次性具体委托，写明条目、允许修改字段、依据、禁止改动部分和完成后的核对方式。总协调 Codex 不因负责总计划就自动取得再次委托权限，须有展的明确授权；笼统的“帮忙整理”不作为委托。

以下提示词由展转交，附上本文在GitHub的链接即可：

```text
请阅读 docs/ROADMAP.md 的“总协调与实施交接”，按已获授权范围继续任务。
实施 Codex 负责本任务源码、测试、必要文档、Issue和PR。总计划#1正文由总协调 Codex统一维护。
请在原任务或PR下按文档格式留【项目更新交接】，注明采用本约定，并把评论链接交给展，请展转交总协调 Codex。
局部小改自行验证，影响多个部分的改动说明调用关系、影响和验证证据，交总协调 Codex额外复查；重大变化由展决定。
已有明确授权先按原范围保留，切换不清楚时说明冲突，不自行改总计划或扩大范围。
总协调 Codex暂时不在时，继续已授权工作并保留待同步记录；没有处理回复不算已同步。
```
