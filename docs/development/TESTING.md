# 测试与验收

测试要说明代码版本、输入、预期、实际结果和边界。语法通过、函数存在、历史记录声称通过，都不能单独代表业务正确。

## #4 单条与整组范围回归

`npm run check` 现额外执行 `scripts/schedule-scope.test.cjs` 的 17 项范围测试，共有 24 项 Node 测试。测试在 VM 中关闭 App.init，只替换 DB 的存储边界并记录合成写入，不接触真实浏览器资料，不调用模型。实际调用解析、原话校验、确认与执行方法，检查最终任务数据、持久写入、删除 ID、操作记录、其他日期与宠物状态，不只检查回复。

历史检查脚本保留不变，三项探测仍全部运行；包装脚本现在要求单天探测返回 `update_schedule`，另外两项仍复现 #5 和 #7。原始失败报告继续保留，不把两项未修复问题计为通过。范围详见[#4 报告](../audit/2026-11-15/issue4-scope.md)。下文 #3 的 7 项工程测试和三项问题记录为当时交付背景。

## 当前源码基线检查

统一入口为 `npm ci --ignore-scripts`，然后 `npm run check`，依次构建、检查文档链接、运行基线包装脚本与 7 项工程测试。任一失败均非零退出。干净下载没有 dist，单独执行下方历史脚本前须先 `npm run build`。

工程测试检查产物字节、来源与重复构建，错误语法、缺失输入、缺失提交、未知产物保护，以及两种预览的 HTTP 文件边界。测试只在临时副本和随机本机端口运行，不启动应用、不读浏览器数据、不调用模型。

`scripts/check-baseline.cjs` 保持原始脚本不变，要求 26 项断言全通过，另核对三项已知问题探测结果。问题不是通过项；探测变化也会失败，须随对应修复任务审查，不能静默删除或跳过。报告写入被忽略的 `.reports/baseline.json`，不覆盖历史证据。

`.github/workflows/check.yml` 在 main、codex 分支推送及面向 main 的 PR 上运行，在 Windows 和 Ubuntu 对检出副本与无 Git 归档分别执行全部检查。仅只读仓库权限，不注入 secrets，不使用 `continue-on-error`。上传仅限 dist 的两个生成文件及合成报告，失败详情留在日志。

本地复验无 Git 归档用 `npm run check:archive`。它归档当前已提交的 HEAD，在系统临时目录执行安装和全部检查，核对来源后清理；不包含未提交改动，也不代替 GitHub ZIP 实际下载验证。#3 的两种下载与 CI 证据见[交付报告](../audit/2026-11-15/issue3-toolchain.md)。

任务 #2 已保存原始新增源码并补充验证，以下命令适用于克隆和 ZIP 下载。版本、干净副本结果及验收见[基线交付报告](../audit/2026-11-14/issue2-baseline.md)。旧版本缺失函数的失败证据保留在[当前状态的历史记录](../STATUS.md)。

```powershell
node docs/audit/2026-11-14/check-baseline.cjs
```

需要 Node.js，无额外项目依赖。脚本在 Node VM 中提取页面函数，跳过 `App.init`，注入合成状态，不读取浏览器数据库，不调用模型、天气或其他网络服务。脚本不读取个人备份或本地图稿，运行不需要私人文件。

脚本输出两类结果：`checks` 为局部断言；`observations` 为已知问题探测。首次盘点的本地代码中有 21 项通过，同时复现了三个问题。正常退出不代表这三个问题已经解决。

当前 26 项局部断言包括原有 21 项和新增的请求取消、城市续答、规划依据过滤、资料框保留及前端整组删除身份。三项已知问题仍在 observations 中单独记录，不计为功能已修复，后续分别由 #4、#5、#7 处理。

脚本可接受一个报告输出路径。新报告放独立日期目录或本地工作目录，不覆盖已归档的 `baseline-results.json`。新报告自动记录执行时间、时区、源码哈希、Git 提交与工作区状态。ZIP 没有 Git 信息时这两项为 null，依源码哈希核对版本。

页面 `App.selfTest` 是启动时控制台自测，覆盖范围和独立脚本不同，目前不能作为可靠 CI 入口。

## 后续检查层次

| 层次 | 验证内容 | 注意 |
| --- | --- | --- |
| 规则 | 日期时间、积分、单条与整组、冲突、字段校验 | 固定时钟和合成数据，检查边界 |
| 接口与存储 | 写入结果、撤销、重复请求、中断、导入、迁移 | 验证最终状态与事务完成，不碰真实资料 |
| AI 评估 | 识别、动作选择、真实依据、追问、异常和费用 | 保留必要真实模型调用，不能只用模拟回复 |
| 自动浏览器 | 发布、确认、取消、设置与错误反馈 | 使用隔离浏览器资料和明确数据集 |
| 实机验收 | 桌面、安卓、iPhone、输入键盘、通知、跨端 | 阶段交付检查完整旅程 |

自动化用于日常回归，关键界面修改仍需要浏览器检查。最终验收不仅看回复，还核对数据库变化、操作条数、原有数据和宠物积分。

## 合格的验证记录

每次记录至少包含：提交与工作区状态、源码哈希、执行时间和时区、运行命令、合成输入、预期和实际、通过与失败、未测范围。模型测试还要记录模型与配置版本、调用数、耗时和费用。

关键失败不能因为总数大部分通过而忽略。越范围修改、重复扣分、数据无法恢复、账户串用或密钥泄漏会阻塞相关发布。首批 3.0 验收场景与阈值在对应设计任务中确认。
