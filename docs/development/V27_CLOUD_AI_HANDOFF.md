## 实现入口与最小方案

### 已有成果应继续复用

- api/ai.js 是现有 Node.js/CommonJS handler，依赖宿主请求响应接口；api/quota.cjs 通过 Redis Lua 实现配额及请求状态。已有取消、失败补偿和可信北京时间规则，不重写第二套计数。
- index.html 中 AIService 的托管路径目前请求同源 /api/ai；自配路径由浏览器直连供应商。GitHub Pages 不运行 api/ai.js，单独部署后端不会让原同源路径自动可用。
- src/assistant/workflow.js 是共享理解与候选合同；src/assistant/materials.js 已在自配路径提供搜索、抓取和图片读取。V2.6这些能力真实通过，不代表托管路径已具有同等实现。
- V2.6保留了 tasks/todos 中已保存记录的真实编号，候选修订仍使用 card_id/version。不要恢复旧的隐藏持久编号逻辑，否则同聊天删除会再次失去目标；不要增加旧合同兼容转换。

### 推荐接入方式

1. 先验证 Vercel Node.js 运行现有 handler 的实际入口、时间与大小限制、可信客户端 IP 来源、模块打包和环境变量，不预设可以零改动部署。
2. 前端保留既有 Pages 来源及浏览器资料。给托管路径建立一个明确的云端 API 配置，处理正式来源跨域及预检；不偷偷更换页面域名，不增加自动试多个地址或降级到泄露 Key 的兼容分支。若必须换前端正式来源，先说明 IndexedDB 数据可见性与恢复影响并取得确认。
3. Key与计数凭据仅由服务端读取，云端请求实际转发到已确认的 DeepSeek 服务。搜索、链接、图片资料走服务器持钥的固定供应商接口，复用既有只读资料语义与共享候选流程。禁止让前端收到共享Key，禁止构建一个可指定任意供应商地址或携带服务端Key的通用代理。
4. 明确浏览器文件、图片编码、API 请求和云函数的实际大小边界。超限清楚提示并保留原文图片；不能为了部署方便静默截断、压坏图片、降低产品上限或改变模型，有实质差异交展确认。
5. 外部网页和图片内容只提供事实，不能成为确认或执行授权。模型结果继续经确定性校验、当前版本和目标范围检查；程序确认后才写入本机事务，保留积分宠物、附件与无关资料。
6. 保留现有用户自配路径。云端停用、限额或故障时明确说明，不伪造成功，不自动换成用户未同意的收费路径。不会云端同步日程，也不增加登录账户体系或迁移用户数据。

本轮可以做接通云端所必需的正常实现，但不新增兼容处理、框架或大依赖。若判断必须新增依赖、调整合同或改变重要产品限制，先提出具体差异与理由，按 AGENTS 确认。涉及共享模块和 AI 合同，在原任务/PR说明调用关系、影响及验证，交总协调按既定约定复查；不为等回复停止无依赖的准备工作。
