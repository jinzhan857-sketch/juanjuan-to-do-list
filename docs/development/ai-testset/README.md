# 卷卷 AI 日用测试集，第1版

本测试集用于先广泛发现问题，再对失败区域做小范围、多样化复现，最后按共同原因归并成GitHub任务。它不是已经执行完的测试报告，也不是承诺覆盖所有可能输入。

当前共有160题，20类，每类8题。全部状态为未执行。本次仅准备资料、核对当前代码与界面入口，不调用真实模型、不增加#81已用满的调用额度、不修改应用功能。编制基线为main eb520b8，2026年11月15日；后续每轮记录实际源码及模型版本，不能把此基线当作正式网站版本。

## 从哪里看

- [全部160题](cases.md)：测试入口、准备、原话或步骤、可接受结果及禁止行为。这里是用例的主要维护位置，编号不随排序变化。
- [合成场景](fixtures.json)：固定时钟、种子记录、同名组、记忆、附件及网络替身说明。只使用虚构资料。

## 先统一判定，避免为了通过而改答案

每题检查三个层次：理解与回复、程序清洗及确认、最终持久化状态。只说“我已安排”或HTTP 200不算执行成功。需要新建、修改、删除时，未经确认不得写入；只讨论、查询或追问时业务记录不得变化。

自然语言回复按语义判定，不要求逐字相同；日期、时刻、目标编号、数量、来源与权限按明确条件判定。AI基础分要求有效范围及可解释性，不强制每次给同一个小数；只有快速发布规则分按已确认规则核对精确值。风格不佳与字段错误分别计，不用流畅文案掩盖误写。

发布表单与助手的现行合同有区别。例如发布一框仍是一条，不自动拆成多条；发布的明确日期时间优先走本地规则。助手支持有限重复组动作，但跨日时间修改需转表单核对。不能把一条入口的规则直接套给另一条。

## 第一轮：广泛探索

1. 在每类抽首个安全代表题，先做20题小规模预检，确认环境、记录方法和费用估算有效；不是先跑同一题20次。
2. 再覆盖每类余下的题，保持20类均有样本。无模型路径、工具替身和故障注入先免费验证，真实模型另按批准预算分批执行。
3. 每题从指定场景副本开始；标明托管或自定义路径、角色、真实或模拟模型、真实或模拟工具。两条模型路径的同题结果分别记录，不能互相代替。
4. 每条模型回答与真正写入分开记录。确认、刷新、撤销等步骤按题目完成；不该写入的题直接检查零写入。
5. 一题有多轮、双路径或重试时，每次实际请求单独计次数和费用。160题不等于160次模型请求，也不意味着必须一次跑完。

结果使用：通过、失败、无法判断、被环境阻塞、待明确需求、未执行。未执行和阻塞都不算通过；未明确的产品选择先讨论，不能由测试者临时决定然后算Bug。

## 第二轮：只对失败区域扩展

保留第一轮原题和原失败，不覆盖答案。围绕一个疑点先选8至12个有区别的变体，不要求把所有组合穷举：

| 方向 | 扩展方法与用途 |
| --- | --- |
| 同义表达 | 换句式、语序、口语或中英混写，核实是否只对某个词有效 |
| 正反例 | 保留同一词但改变意思，例如“三点复习”和“整理三点建议” |
| 边界 | 相邻日期、午夜、月末、空字段、长度临界值，明确失败范围 |
| 单因素 | 每次只改变一个条件，例如原话相同，只换角色或手选日期 |
| 上下文 | 空资料、唯一目标、同名多目标、140条背景，检查依赖是否明确 |
| 多轮位置 | 原话、下一轮更正、切角色、切聊天，区分当前输入与历史污染 |
| 执行阶段 | 模型原文正确但表单或数据库错误时，停止改提示词，检查程序映射与确认 |
| 稳定性 | 同输入、同场景、同配置重复若干次，报告失败次数/尝试次数；次数及预算先确认 |
| 路径对照 | 托管与自定义分别记录；模型、提示词或工具不同就不能直接当成同条件对照 |

先找到最小复现，再扩大到邻近场景；不要用不断重试直到成功的最后一条覆盖前面的失败。某种表达失败、对照表达成功可形成定位线索，但不是单凭相关性宣布根因。

## 第三轮：归并问题并排队

先查现有Issue。已存在的问题补原任务；原任务已关闭而新版本复现时说明是否回归，不默认重新打开整项。多个失败题若共同原因相同，归成一个任务，并列出关联题号；同一题可暴露多个不同层次的问题，不能强行合为一个。

状态依次区分：已记录、待复现、已复现、原因假设、根因已定位、待修复、已修复待验、已验收。单次不稳定异常可先登记待复现，不必等“测很多次”才留证据。关键误删、泄露、越范围写入或重复奖励出现一次清楚证据，就立即停止对应执行并登记，不靠累计失败数量才重视。

每个Issue写问题、影响、复现题号、固定资料、预期与实际、失败频率、确定与不确定原因、最小修复范围、验证办法、停止条件。加入总计划#1时按风险和依赖排期，不自动插到所有任务前面，也不把每题变成一个Issue。本轮只准备测试集，不预先宣布问题总数或创建160个任务。

## 修复后的复测

先跑原失败题、同一区域正反例和第二轮变体，再跑相关邻接类别，最后做跨类别回归。用同版本场景、固定时钟和一致的判定规则比较修复前后，保留原始失败、修复提交与新结果。改动只使特定原句通过而相邻表达失败，不能算根因已解决。

这是一套公开可见的回归基线，不称为模型未见留出集。若需要检验泛化，修复后另写新的日用表达，并按语义家族隔离；看过失败并据此调过提示词后，这些题就属于已知回归资料。

## 环境与停止条件

固定默认时钟为北京时间2026年11月15日10:00，特殊题显式换场景时钟。天气替身用于可复现检查，真实天气另记录当日时钟、工具来源与查询时间，不硬比固定温度。

只在专用来源、独立浏览器资料或独立测试数据库导入合成场景。fixtures.json不是可直接导入的业务备份，不能拿它覆盖用户资料；应通过现有隔离测试准备完整对象。不得从日常浏览器读Key、私密备份、相册或真实聊天充当样本。密钥仅由本机私有配置提供，不写入题目、回答、截图或GitHub。

本轮没有真实调用预算。执行前先与展约定本轮范围、最大尝试次数、输入输出规模和金额预算；按实际请求计数，包括失败尝试。模型费用与卷卷公共次数退回不是同一回事。达到任何已定上限、出现真实资料访问、误写、泄露或无法恢复时停止对应执行，保留证据；不得删账本、自动重试、重开工作区或换Key绕过限制。
