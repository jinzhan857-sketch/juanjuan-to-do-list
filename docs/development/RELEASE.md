## 当前正式静态入口与发布

正式入口：<https://jinzhan857-sketch.github.io/juanjuan-to-do-list/>。2026 年 11 月 15 日，展明确改为公开仓库并恢复免费 Pages，替代本轮早先保持私有的选择，不新增套餐或托管账号。个人备份、密钥仍不入库，项目尚未选择开源许可证。

Pages 设置选择 GitHub Actions。执行者在 Actions 进入 Publish GitHub Pages，选择 main 后手动 Run workflow。工作流只允许 main，先安装锁定依赖并执行 npm run check，再上传 dist，部署成功后核对网站与 build-info.json 的提交及页面 SHA256。代码推送和 PR 不自动发布。只发布构建产物，不把仓库根目录、api 源文件或私人资料作为网站上传。

发布工作流为 .github/workflows/pages.yml，构建仅有 contents: read，部署仅授予 Pages 与 OIDC 必需权限，没有业务 secrets。失败时不继续部署，保留原有站点。回退时从确认的 main 回退提交重新检查和手动部署，不修改用户数据库。

GitHub Pages 仅提供静态文件，不执行 api/ai.js。托管 AI 接口和业务云端同步需后续任务单独接通；自定义模型仅按用户原设置使用，不发起本轮真实模型测试。恢复同一网址不需要迁移浏览器数据。历史 Sites 地址仍保留，版本 8 来自 b35936b，手机可访问性未通过，不作为本次正式入口。

## 当前构建流程

#3 已提供 `npm ci --ignore-scripts` 与 `npm run check`，成功后生成 `dist/index.html` 和 `dist/build-info.json`，预览用 `npm run preview`。dist 不再入库，禁止手工复制维护，评分模块 dist/quick-score.mjs 同为必要产物，不可遗漏；模块输入哈希随来源记录保存。来源与哈希规则见[开发说明](README.md#构建与来源)。

正式发布应选已审查提交对应的干净 CI 产物，并保留运行链接、提交和哈希。dirty 为 true、来源缺失、检查失败或构建中断时停止发布；ZIP 的 dirty 为 null 不是已确认干净，应与对应提交的 CI 哈希核对。不能沿用旧残留产物。

构建只生成静态页面与来源文件，不打包或启动 AI 接口。Sites 配置仍指向 dist，部署前须先构建，并另外确认接口宿主。常规工程 CI 不部署，Pages 由单独手动工作流在明确授权下发布。本次恢复证据见[#40 报告](../audit/2026-11-15/issue40-pages.md)。下方首次盘点记录和待完善的完整发布要求继续保留。

## 当前发布事实

配置文件 `.openai/hosting.json` 声明 Sites 静态目录为 `dist`。首次盘点时该文件是未自动生成的旧版本，历史产物可从 #3 之前的提交追溯，本次改为生成并不表示线上已更新。

Sites 最近核对的保存版本为第 8 版，来源应用提交 `b35936b…`，平台显示部署成功。命令行对首页和 API 的历史探测返回 403，未完成普通浏览器与真实 API 的完整验收。详情见[现状清单](../CURRENT_STATE.md)。

当前 GitHub 文档更新不会自动证明线上应用已更新；也不能凭 `.openai/hosting.json` 保证 Node 接口已经托管。不要向曾触发凭据弹窗的 `sites-publish` 远端填写密码或试推，后续发布通过已确认的平台能力处理。

## 正式发布前要建立的流程

1. 确定应用代码提交、版本号与发布范围，保证未提交成果有明确归属。
2. 用可重复命令生成发布目录，核对产物来源，消除手工复制漂移。
3. 执行相关规则、存储、界面与必要模型检查，归档结果。
4. 核对配置、前后端路由与目标地区可访问性，记录不含密钥的配置名称。
5. 涉及数据变化时先确认备份、迁移与恢复演练。
6. 在已授权范围内部署，完成线上冒烟检查，再记录版本标签、Release、平台版本与证据链接。

这是一份待落实的发布要求，不是当前已可一键执行的命令。页面展示版本按展于 2026 年 11 月 15 日的确认更新为 V2.5；备份格式仍由现有 2.2 数据格式单独控制，3.0 仍是后续建设目标。

## 回退与停止条件

代码回退、平台回退和用户数据恢复分别验证。保留旧应用提交及产物记录，确认平台回到哪个版本；数据恢复使用独立备份与已演练步骤，不能用 `git reset` 当作数据库恢复。

出现数据覆盖风险、越范围修改、关键测试退步、配置无法复原或核心链路不可用时，停止本次发布，保留错误和测试证据。不在用户数据上临时清空或通过重新部署掩盖问题。

Git 标签、Release 和站点回退流程都需要后续任务实际验证，见[路线图](../ROADMAP.md)。
