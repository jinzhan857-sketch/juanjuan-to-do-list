# V2.7 公共额度与设备体验卡

展于2026年11月17日确认：普通设备每天300次、每周300次，全站公共池每周1000次，不按IP限制。日额度在北京时间零点切换，周额度在北京时间周一零点切换。用户传入的日期不改变额度周期。获准请求同时原子预占三个约束，失败与取消去重退回；日上限和周上限分别保留，可独立调整。

专属体验采用累计额度卡，替代讨论中的每周恢复体验码。首次兑换绑定当前浏览器设备编号，默认不设到期时间。可以开500次、5000次等余额；每次成功服务请求扣一次，失败和取消退一次，不受公共日限额与周限额约束，不占全站公共池。一条联网请求可能包含多次收费模型或工具调用，体验卡余额不是供应商收费请求数，也不保证供应商费用与次数固定对应。普通预算与专项真实测试账本仍分别按原授权执行，不能通过体验卡追加200次、1元的测试授权。

## 用户操作

进入“我的，大模型配置，卷卷提供”，粘贴兑换码，点击“兑换体验卡”。确认后在最下方“目前状况”显示云端余额或公共额度状态。问题咨询说明与“复制设备编号”按钮左右排列，按需复制编号给开发者。卡和设备凭证只在当前浏览器保存，不随业务备份导出，不发送给自定义模型。刷新或关闭浏览器不影响；清除网站数据或换浏览器需要人工重新绑定。云端保存余额和原绑定，重新绑定不恢复已消耗次数。

已停用、过期或设备不匹配会明确拒绝，不会偷偷改用公共额度。用户可点击“切回公共额度”，此操作只移除本机卡凭证，不清除云端余额或解绑。日程、聊天、记忆、宠物及积分仍在各浏览器，卡不提供账号或资料同步。发码备注只用于拥有者管理，不代替收卡人的账号。

## 无管理员页面的发卡与维护

工具只在已授权仓库读取用户目录`.config/juanjuan/v27/cloud.env`中的私有数据库配置，不读取模型Key。所有写操作要求显式`--apply`。不要把输出的真实兑换码放入GitHub、文档或截图。

```powershell
node scripts/v27-experience.cjs create --label "朋友小王" --credits 500 --apply
node scripts/v27-experience.cjs create --label "我自己" --credits 5000 --days 30 --apply
node scripts/v27-experience.cjs topup --id <卡编号> --credits 500 --apply
node scripts/v27-experience.cjs rebind --id <卡编号> --device <新设备编号> --apply
node scripts/v27-experience.cjs revoke --id <卡编号> --apply
node scripts/v27-experience.cjs reset-public --apply
```

不传`--days`即不设到期时间；有效期从发卡时开始，填写天数时为1至365天。每张卡总授予额度最大100万次，充值保持历史扣次记录。收款由展自行线下处理，卷卷未接支付。当前不默认给任何真实用户发卡，展指定对象与数量后再发。绑定变更或停用会在下一次原子预占中重新核对，已获准进行中的请求仍可能完成。

恢复公共周额度通过切换本周计数命名空间完成，历史统计与旧请求退次记录保留，不删Redis库。该操作恢复公共周池和公共设备周额度，不修改当天设备日额度、体验卡余额或供应商账单。恢复卡的可用次数使用明确充值，不重置已消费记录。

## 计数与安全边界

公用计数与卡余额共用原子预占、成功、退次引擎。公共计数键保留9天，周期重置依赖可信日期键切换，避免一周中途因24小时TTL提前恢复。卡消费成功成员不设过期，跨周不恢复；失联请求的待处理租约60秒后释放，不把超时请求永久扣成成功。卡的成功请求收据保留，支持迟到退次；失败与取消收据保留9天防重放。

兑换码含随机编号与128位随机秘密，云端只保存秘密的SHA256。第一次绑定使用Redis原子脚本，多个浏览器同时兑换只允许一个成功。发卡、充值、停用与人工重绑使用本机私有配置，没有新增公开管理接口，也不复用只读统计口令获得写权限。

测试入口与原Pages的浏览器资料相互隔离。仅更新[云端测试版](https://juanjuan-v27-ai.vercel.app/)，正式Pages仍待展验收，发布流程见[V2.7说明](V27_RELEASE.md)。
