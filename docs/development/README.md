# 本地开发与接手

先读[当前状态](../STATUS.md)和根目录 [AGENTS.md](../../AGENTS.md)。本页提供现有可执行入口，统一依赖、构建与完整后端启动仍是待做任务。

## 准备仓库

需要 Git、Node.js 与 npm/npx。本轮使用 Node.js 24 验证。私有仓库需获得访问权限；下载 ZIP 不包含 Git 历史，可供试运行，提交协作应使用克隆。

```powershell
git clone git@github.com:jinzhan857-sketch/juanjuan-to-do-list.git
cd juanjuan-to-do-list
git status --short --branch
```

如果已有展的本地目录，直接使用现有目录并核对状态，不重复覆盖下载，不运行清理或强制重置。`index.html` 与 `api/ai.js` 的原始新增成果已通过 #2 保存，版本和未发布边界见[基线交付报告](../audit/2026-11-14/issue2-baseline.md)。仍需实际检查工作区，保护后续未提交成果。

## 启动静态预览

```powershell
npx --yes http-server . -a 127.0.0.1 -p 4173 -c-1
```

打开 <http://127.0.0.1:4173/>。该命令首次会下载 `http-server`，当前没有项目级依赖锁定；后续统一运行入口时再固定工具版本。停止使用 `Ctrl+C`。

服务只绑定本机地址。目录可能含个人资料，不把目录列表、端口或隧道分享出去。4173 已被占用时先核对是否是本项目预览，不盲目结束其他进程。

根路径读取 `index.html`，访问 `/dist/` 则读取另一份页面。两者可能不同，调试时必须注明正在看哪份。不要使用 `file://` 作为标准验证方式。

处理界面、交互或功能迭代时，按项目规则先启动 4173 预览并在内置浏览器确认页面加载。数据操作测试需要隔离资料；页面启动自身也可能执行规范化和宠物跨日结算，不把普通打开说成完全只读。

## AI 与后端

静态预览可检查页面和本地能力，但 `/api/ai` 不会因为文件存在而工作。浏览器中可通过“我的”模型设置填写自定义服务，使用合成输入测试；不要把 Key 写入脚本、截图和提交。

完整托管链路需另外配置宿主路由、环境变量与 Redis，当前没有已经验证的一键命令。不要执行 `node api/ai.js` 后宣称后端已启动。要求见[AI 说明](../architecture/AI.md)。

## 日常检查

```powershell
node scripts/check-docs.cjs
git diff --check
```

以上检查文档链接。业务检查使用 `node docs/audit/2026-11-14/check-baseline.cjs`，#2 已保存与检查匹配的源码。检查含义、合成数据和已知问题见[测试说明](TESTING.md)。当前没有 `npm run build` 或完整 CI，文档检查通过不意味着核心流程已通过。

## 修改与提交

每项工作先看对应 Issue 的范围和前置条件，从合适的主分支提交建立 `codex/` 任务分支，修改后执行相关检查并关联 PR。不要把其他任务的未提交源码顺手加入文档提交。

提交说明用英文。展不需要操作 Git，由执行者完成保存和已授权范围内的推送。实际发布与恢复另见[发布说明](RELEASE.md)，GitHub 上传和站点部署必须分清。

目录整理不应附带改业务、换框架或新增兼容处理。遇到数据恢复无法保证、关键测试退步、越范围写入等情况，停止相关发布并记录原因。
